## 1. 它是什么

本小程序是 **ForgeaX** 的游戏创意前置共创：用户丢一个贫瘠脑洞，经过一轮灵感引导和共创对话，得到一份人可读的游戏设计文档（GDD）。文档目前是**手动交给** ForgeaX 继续做游戏，不在本产品里做选型、编排或可玩原型。

**品牌：** 用户看得到的产品名一律写 ForgeaX（F 和 X 大写）：导航、Tab、首页、共创、我的、关于、协议、开场白、文档封面、分享卡和分享标题。品牌出现时写对，不为了品牌多放几次。仓库名、npm 包名、import 路径、`nb.` 存储键、旧提示词文件名这些内部工程名称暂未迁移，以后单独改。

**界面文案：** 去冗余，不去人格；减说明，不减定位。删掉重复解释、按钮已经说清的说明、开发者视角和技术语言。保留产品定位、主句、原始开场白、适量的品牌氛围和装饰文字、协议确认、删除确认、错误恢复和生成中 / 失败 / 已过期这些状态。GDD 正文不按这条删改。

一句话链路：

```text
脑洞 → 同意引导 → 按节澄清（带方向卡）→ 口头概念总结 → 定稿三选 → Interactive GDD 预览 / 分享卡片 / 导出文件
```

**不是**「填一句 prompt 就出完整游戏」，也不是当前 README 旧稿里的 DSL / match-3 / catalog 选型。仓库里还留着那些包和历史设计文档，它们**不是**现在对用户承诺的产品。

## 2. 成功长什么样

用户走完一轮之后，应能指着屏幕说：

- 这就是我想做的游戏（有暂定名和一句话亮点）
- 我是自己点「定稿」才看到文档的，不是系统自己弹出来的
- 中间每问到一个设计缺口，我都能点方向，也可以自己打字
- 出文档之后我还能继续改：可以在共创里打字走定稿三选，也可以在预览里点手风琴一句，高亮后点「修改」，确认后只改清单里的那些地方

## 3. 用户看见的流程

### 3.1 开口

助手先打招呼，请用户随便说一个画面、玩法或角色。用户无固定身份。

### 3.2 同意门（宿主写死）

用户说出想法之后，再问要不要走创意引导。文案大意：大约 **10 轮**提问，把创意澄清成设计文档。

固定两张卡：

| 选项 | 行为 |
| --- | --- |
| 是，开始创意引导 | 进入采访。下一句必须已经在聊他的创意，不再问要不要走流程 |
| 不用，先不走这个流程 | 自由说想法，不投喂方向卡，能确定的就记下 |

**「大约 10 轮」只是给用户的范围，不是收口条件。** 到第几问、出不出三选、出不出文档，都不数轮次。内部按大约 15 问排：前面四节可以稍多，后面四节收短；子项能合并就合并。不改同意门文案。

### 3.3 采访（模型写方向，宿主要卡）

同意之后，按节问（已能跳过的节除外）。每轮：

1. 人话：共情 + **一个**问题（不要在气泡里再列 A/B/C）。问方向的那一句单独加衬底，一眼看到在问什么；开场、总结、补丁那种不问方向的轮次不加。流式时就按最终版式排，出卡时不把第一段换一遍
2. 紧跟着的**第二段气泡**里 **2–3 个实质设计方向**：彼此真正不同，label 自带画面，说明默认露出来，不写「方向 A」。**点一下即选中**，不要先展开再点第二次
3. 点完的那一张从原位**一段动作**斜着变形成右侧用户气泡，其余就地淡出。用户气泡和「…」的高度在飞之前就占好。选项收起，以及「新气泡会落到屏幕外时把列表带进可视区」，是**同一段**缓动，和飞行动画一起走完。已经在屏幕里的气泡停在原地。飞行从输入框下面穿过，不盖住输入框。落定后「…」从下方滑入；这两步都不再瞬间改滚动位置。气泡上留 label 短句，发给宿主的仍是完整说明
4. 输入框始终是开放口，**禁止**「我有其他想法 / 自己输入 / Other」做成卡片

节的顺序（对用户不要报「第几节」）：

| 内部节 | 要聊清什么 | 能否跳过 |
| --- | --- | --- |
| 破冰 | 用户已经开口 | 已开口则跳 |
| 火花 | 兴奋点（`spark`） | 已有脑洞则心里钉住即可 |
| 核心体验 | 主情感、世界或主题、视听氛围（不问点/拖） | 否；缺口能合并就合并 |
| 核心交互 | 怎么操作、操作谁、屏幕立刻怎样；一句带 → 的链路 | 否；一轮可写多个字段 |
| 核心循环 | 头几秒、奖励/失误（能填则填）、最舍不得删的瞬间 | 否 |
| 成长与变化 | 越玩越多、眼前目标、玩一阵后能做的新事 | 用户或循环里已标明短局 / 一次性 / 纯叙事 / 无长线则可跳；只写 `growth.none` 不够 |
| 美学与手感 | 高光夸奖或手感隐喻，一轮 | 否 |
| 世界与叙事 | 世界或故事 | 已有世界/叙事可跳 |
| 平衡与心流 | 怎么上强度或为什么再来一把，一轮 | 否 |
| 呈现 | 在哪玩、平面还是立体。不问手指怎么点 | 否 |

前面四节（体验 / 交互 / 循环 / 成长）可以稍多；后面四节（美学 / 世界 / 平衡 / 呈现）大约各一轮。列出的子项按缺口合并，不必一问一项。

核心体验、核心交互、核心循环、美学、平衡、呈现：**必须各问至少一轮**，即使模型已经顺带写过字段。

### 3.4 口头概念总结 → 定稿三选

宿主先判定 **核心体验到呈现都已经按节问过**（内部到达第 10 节 / 呈现问完，`may_write_summary: true`）。这之前提示词要求模型不要写暂定名；**一旦人话里已经流出合格概念总结（含提前写出的），第二段气泡必须出定稿三选**，不得改成采访卡，也不得把气泡换成另一段采访问句。

到达第 10 节之后，本轮必须出口头概念总结。完整度清单（禁止情感、六池关键词等）**不挡住**写总结，也**不挡住**出三选。那些缺口只影响内部 `gddComplete`；预览顶上亮不亮「这是草稿」见 §5.3，版面上打不打「（未写）」见 §5.5。

助手人话出现**合格概念总结**之后，换成宿主写死的三张卡。

合格总结必须同时有：

- 游戏名：`暂定名` / `暂定游戏名`，或 `《标题》`
- 总结块：`📌`，或「概念总结」，或「一句话亮点」

只说「骨架已经清晰」「蓝图已经成型」**不算**。模型 JSON 里出现定稿项也**不能**换卡。

**流式人话在弹出卡片时不得替换。** 纠偏只补卡片，不换段落。本轮气泡是总结 → 三选；本轮气泡是提问 → 该问的方向卡。

总结出现后：

- 内部进入收敛节（不再继续塞呈现采访）
- 已流出的追问留在气泡里，不裁
- 第二段气泡里固定三选（和采访三选同一套交互：点一下即选中、变形进用户气泡）：

| 选项 | 行为 |
| --- | --- |
| 就按这个定稿，写成设计文档 | **当轮没有方向卡**，出 GDD。聊天列表和输入框之间出现「游戏文档已成型 / 打开预览」 |
| 核心对，但要改某一块 | 先出一轮针对「改哪一块」的实质方向卡，用户点完再回到这三选 |
| 还想再挖挖感觉 / 玩法 | 同上，先一轮设计方向，再回到这三选 |

用户也可以打字「现在就生成」：采访中途立刻出带缺口的半成品，下一轮继续问；口头总结之后效果等同点定稿。

### 3.5 出文档之后

分两种：

- **采访中途主动要文档**：出带缺口的草稿，当轮没有方向卡，下一轮继续当前采访节。不跳到定稿三选，也不要求完整度。
- **点定稿（或总结之后再说要文档）**：之后再开口是在现有文档上改，不再按节采访。按修改从哪里发起分流，不看用户说得够不够具体：
  - **共创页输入框提新想法**（`iterationOrigin = cocreation`）：固定一轮采访三选、一轮定稿三选。哪怕想法已经很具体，也先围绕这句问一个最值得决定的方向；用户回答（点卡或打字）后下一步一定是定稿三选，不会再问第二轮，之后再打字也还是定稿三选。点「就按这个定稿」更新文档并结束这次修改；真的点了「改一块 / 再挖挖」才算新的一次修改，又采访一轮。采访那一轮和出定稿三选那一轮各只调一次模型，不用整段对话重抽整份文档；点定稿那一轮才重抽。
  - **文档页点某一条「修改」**（`iterationOrigin = document_patch`）：不出采访三选，流程见 §3.7。
  - 会话上记有 `gddFinalized`，旧会话按「出过文档且有合格总结」认。

两种都可以打开预览、用小程序卡片分享 **GDD 快照**（不带聊天记录），主人还可以导出 Markdown 文件交给 ForgeaX。文档按采访来写，可以润色延申；没聊过的作品名不要写。

文档出来之后，共创页在**聊天列表和输入框之间**放一张文档入口卡。点卡片主体进预览。卡上至少有：游戏标题、一句话亮点（没有就不占行）、封面。封面位尺寸固定：生成中写「封面生成中」，失败写「封面没生成」，还没有封面写「暂无封面」，有图才换上封面，换图不改变卡片高度。没有文档时这张卡不存在、不占高度。出现时淡入上移，对话让出它的高度；之后翻聊天它停在原地，不跟着滚。继续聊时卡片留在原地，不先收起再弹出。再改文档只更新这张卡，不另起一张。键盘把输入框顶高时，卡片跟着上移。

同一张卡上可以直接 **分享给朋友** 和 **导出 GDD 文件**，规则与预览页相同，见 §3.8。补丁三选出现时藏掉这张卡。

预览上手风琴一行的改法见 §3.7，不走本节的定稿三选。

### 3.6 不同意引导

不弹方向卡。用户自己说，系统只记能确定的部分。他若主动要文档，仍按「有实质内容 + 用户要文档」出草稿。

### 3.7 预览里点一行改

出过预览之后（含中途半成品），用户可以在手风琴里点**一行**来改，不必整份再定稿。

**能点：** 核心动作、交互链路、编号机制、宪法、标了「（未写）」的行，以及其它手风琴正文行。

**不能点：** 封面、游戏类型、关键瞬间、底部完整文档里的句子。分享页只读，不能点行。完整文档可以整段展开或收起，那不是上面的章节手风琴。

流程：

1. 点一句先出荧光绿描边，背景和字色不变。这一行下面展开「修改」和「取消」。点「修改」才回到**同一条**共创。点「取消」或再点这一行，描边和「修改 / 取消」同一段收起，描边不在操作消失后再留一会儿，不改文档。换到另一句时，上一句描边消失。助手只问这一处想怎么改，不报第几节，不出定稿三选。刚问怎么改时还可以打开预览。补丁三选出现时，藏掉「游戏文档已成型」。
2. 用户说完后，**同一轮**用大白话列出文档里会改哪些地方、改成什么（不说「手风琴」），并在第二段气泡里给出补丁三选（宿主写死，不是定稿三选）。改成什么写全句，不截断、不加省略号；从历史重新进入也是同一段全文。写入的字段只留改完后的现行正文，禁止「不再需要旧的，而是通过新的」。

| 选项 | 行为 |
| --- | --- |
| 应用这些改动 | 只把清单里的字段写入文档，再编预览并回去看。清单外的字段不动。第一版不能单行勾选，点应用等于整包接受。点的是某一条核心机制时只改这一条，其他机制原样；这一条的关键瞬间跟着换字，身份不变，只有它的玩法图标「已过期」。写回后回一段完整回执，列出改了哪里、改成什么 |
| 再改改说法 | 不写文档，留在共创继续说这一行；说完再出清单和三选 |
| 取消 | 不写文档，回预览。这次点进来的对话留在历史里 |

核心机制正文不带「1. / 2、」这类序号，序号只在文档和手风琴展示时按位置加。点某一条修改时，问用户的那句只给原句；模型写回时带了序号也会先去掉，旧会话里已经存成「6. xxx」的，展示时同样去掉，身份不变。

这条入口在会话上记 `iterationOrigin = document_patch`，从点「修改」一直保留到应用或取消：点的哪一行（行 id 和对应字段）、原文、用户说的修改要求、将写回的内容都在 `patchContext` 里。中间用户怎么打字都还在这一条上，不会变成整份文档的共创，也不出采访三选。

改完后：半成品还回采访方向卡，接着挖。已经定稿的，**不把定稿三选还回去**，共创里只留「游戏文档已成型」。如果点进来之前共创页那次修改还在采访，取消或应用后照原样接回那一轮，回答后仍只给定稿三选。点应用或取消都会收掉补丁三选。

**封面：** 第一次定稿、还没有封面时，仍自动出第一张。会话里一旦有过封面（成功或失败），再改文档不再自动生图。文档改过以后封面在内部算「过期」，但文档页、共创页文档卡、历史记录卡都照样显示这张旧图。预览上用「重新生成封面」才出新图：画的过程中旧图留着，新图好了原位替换；点封面本身不生图。按钮进行中不可再点；失败只 toast，旧图和文档照常。

**旧分享：** 点应用或重生封面后，以前分享出去的**同一份会话**下的快照会跟着变（仍不带聊天）。旧文件如果没有记下是哪条会话，跟不了，也不迁数据。

完整度门不放宽。补「（未写）」可能让草稿/齐活标记变化，规则仍按 §5。

### 3.8 导出 GDD 文件（交给 ForgeaX）

小程序**写不进** iPhone「文件」或系统下载目录。沙盒里的 `saveFile` 用户在手机里找不到。能把文件拿出去的通路是微信发送面板（`wx.shareFileMessage`）。

预览页和共创页的文档卡各有这两个入口，行为相同，都保留：

| 入口 | 对方拿到什么 |
| --- | --- |
| 分享给朋友 | 小程序卡片。对方打开的是预览页快照，不是文件。快照只读：带封面、游戏类型和源会话里已有的关键瞬间图（和自己打开文档时同一套判定：当前图和文档改过后保留的旧图都显示）；没有图的那条只显示文字，不出现等待生成、重新生成、已过期，打开不生图、不写会话 |
| 导出 GDD 文件 | 一份 `{游戏名}-gdd.md`，内容就是预览里的完整 Markdown，**不带聊天、不带封面图** |

点「导出 GDD 文件」后弹出微信发送面板：

- 选**文件传输助手** ≈ 保存在微信里，需要时再转存。产品文案按这个说「保存在本地」，**不承诺**写入系统相册或「文件」App。
- 选好友 / 群 ≈ 把这份文件发到微信。

「复制全文」仍在，文件没发出去时可以先复制。分享页第一版**没有**导出（对方只有快照；交接仍由主人导出）。仍**不**自动在 ForgeaX 里立项。

`.md` 若被客户端拒，同一次点击改写成 `{游戏名}-gdd.txt` 再发，内容仍是 Markdown。微信开发者工具**模拟器发不了文件**（会提示请用真机），要以真机预览为准。预览页不另写说明文案。

## 4. 谁说了算：宿主 vs 模型

**硬规则写在代码里，提示词只负责把模型往规则上推。** 模型可以忽略提示词；宿主必须把结果扳回来。

| 事项 | 谁决定 |
| --- | --- |
| 同意门两张卡的文案 | 宿主写死 |
| 定稿三选的文案和出现时机 | 宿主写死 |
| 补丁三选（应用 / 再改改 / 取消） | 宿主写死；点应用才写清单字段，不走定稿出稿闸 |
| 采访 2–3 个方向的**内容** | 模型按「选项编写纪律」现编 |
| JSON 没有方向卡时 | 宿主再要一轮 options；**已流出的人话不换** |
| 人话里的 A/B 列表 | 收回成卡片；气泡原文不动 |
| 要不要出文档 | 宿主：用户点定稿或说「现在就生成」（中途也可以） |
| 文档里有没有没聊过的作品 | 宿主：没出现过的作品名丢掉；其余栏允许按采访润色 |
| 模型自称 `ready_for_synthesis` / `stage_complete` | **忽略** |
| 问什么、暂定名叫什么、共情怎么写 | 模型；宿主不编内容 |

选项编写纪律（skill 里有全文，这里是产品约束）：

- 2–3 个方向必须彼此真的不同，不是程度词
- label 自带画面
- 禁止开放口选项
- 已经给了卡片，气泡里的原文仍保持流出时的样子

## 5. 「内容齐了吗」其实是四套门

不要把它们混成一句「AI 觉得齐了」。模型不判断齐全，宿主用字段是否非空来算。

### 5.1 采访能不能问下一节

本节该填的字段已经有字，**并且本节已经问过**，才进下一节。一次只进一节。

常见坑：用户口语里说过「3D 画风」，如果没写进「平面还是立体」，呈现节仍会认为不齐。这会挡住进入第 10 节（因而挡住总结和三选），直到呈现问过并写入。

### 5.2 能不能出定稿三选

看**这一轮已经流到屏幕上的人话**：

- 合格概念总结（游戏名 + 一句话 / 📌）→ 定稿三选，即使还没到第 10 节
- 普通采访问句 → 该问的 2–3 个方向卡，不因历史里曾经有过 📌 就改成三选

第 10 节只决定何时**让模型写**总结（`may_write_summary`），不拿来在出卡时换掉已流出的字。**不等** completeness.md 全绿，**不数**大约 10 轮。

### 5.3 能不能出设计文档

同时满足：

1. 用户点了定稿，或说了「现在就生成」这类要文档的话（采访中途也可以）
2. 对话里已经有一点实质内容（pitch / 情感 / 循环 / 机制等任一有字）

**不要求**已经到达第 10 节，**不要求**完整度清单全绿。主动要文档就给半成品。

预览顶上的「这是草稿」只在**中途**说「现在就生成」这类话、而且助手还没给过合格口头总结时亮。模型已经写出概念总结、用户再点定稿，条不亮——即使内部 `gddComplete` 仍是 false。

文档按采访来写，**可以润色和合理延申**，不必每个字都在对话里出现过。内容边界、呈现边界必须有一句，不能空着。没聊过的参考作品名不要写进去。刷新会话也不能凭空再弹文档。**第一次定稿和之后刷新走同一条抽取覆盖**，不用首句 spark 或固定内容边界把 Pitch、核心幻想、「这是什么游戏」占住。

给人看的文档由代码组装，细则见 §5.5。完整度清单仍按 completeness 算，**不再**用顶上草稿条去标总结后的文档。

### 5.4 文档算不算「定稿完整」

对齐 `prompts/game-gdd-clarify/completeness.md`。缺一项 `gddComplete` 就是 false，但不挡住出文档，也**不单独决定**预览草稿条。完整度里「禁止情感」、六类关键词每类 ≥5、参考作品、宪法等经常是缺口。创新性自检五条**没有写进代码**，只在提示词里劝模型。

这三件事不要混：

| 账 | 管什么 | 不管什么 |
| --- | --- | --- |
| `gddComplete` / completeness.md | 内部是否「清单全绿」 | 不出文档、不挡三选、不单独亮草稿条 |
| 预览顶上「这是草稿」 | 中途「现在就生成」且还没有合格口头总结 | 禁止情感/六池缺了也会在总结后的定稿预览里灭条 |
| 版面上的「（未写）」 | 模板里仍要印的格子空着、且文档不算完整 | 禁止情感、避开、空词池、空参考作品整节——那些是省略，见 §5.5 |

### 5.5 给人看的文档怎么收（版面）

GDD **不是**模型整篇写出来的。会话字段进 `toGddModel`，再 `renderGdd` / 小程序章节卡。GET 会话会重新组装，旧聊天不用重聊，打开预览就是当前规则。

**机制 / 高光**

- 给人看时折叠近义，最多 6 条机制、高光用列表（不要顿号墙）。
- 出稿抽取时 `mechanics` / `juice` **整表替换**；采访中途仍并集，以免聊到一半丢掉。

**空栏：省略 ≠ 从会话删掉**

没聊过的内容，字段在会话 JSON 里可以仍是空的，只是有的不印、有的印「（未写）」。

整行或整节**不出现、不打「（未写）」**：

- 禁止情感
- 刻意避开
- 参考作品（借鉴和避开都空则整节没有）
- 关键词池（见下）
- 游戏宪法里没确认过的项（核心幻想、核心循环、美术规则、内容边界、呈现边界、成长规则、世界观规则、UI 规则这八项里，没聊过的整行删掉）。失败规则、爽点、难度不是宪法项，不要灌进宪法。

模板里其它格子（Pitch、循环、疲劳、屏幕方向等）**标题还在**。空着且 `gddComplete` 为 false 时，Markdown / 章节卡仍可能写「（未写）」。完整度全绿时空栏改成「本游戏无此项，不单列。」一类话。

**关键词池（六池）**

六类：玩法 / 情绪 / 世界观 / 视觉 / 叙事 / 玩家动机。

- **不问**：不要为凑齐六池单开一轮采访。
- **不回填正文**：禁止把核心动作、机制段落、整句情绪切碎填进池子。
- **只留短词**：无句号/问号/冒号，大约不超过十二个字；每类最多 10 个。句子进不了池。
- **空则省略**：某一类没有短词就不出那一行；六类都空则整节「关键词池」不出现。
- **完整度仍要每类 ≥5**：这是内部账，经常因此 `gddComplete` 为 false；不因此在总结后的预览顶上亮草稿条。

所以会出现：发光食堂六池在会话里是空数组 → 文档没有这一节；香火未尽抽取时写下了「塔防、香火、老宅」这类短词 → 六行都在。不是两套规则，是两份会话当时有没有留下短词。

**其它版面**

- 核心幻想和玩家身份：一段已经包含另一段就只留一段，不要拼出 `。。`。
- 游戏宪法只印已确认的八项，顺序固定；没聊过的行省略。
- 内容章不要把世界和核心动作硬接在一起。
- Markdown / 手风琴「怎么玩」印核心动作、核心交互、核心机制；循环、爽点、奖励、成长印在「为什么继续玩」。预览不再把这些摘成基因、分镜或三环。
- 宏循环用三十分钟循环；长线目标和它不是一回事时多写一行「长线」。
- 「要和别人一起」就打开多人章（排行榜/偷师等），不要只停在呈现栏口语。

### 5.6 Interactive GDD（结果页）

结果页不是「再让模型写一版 UI」，也不是把 Markdown 扔掉。三套账分开：

1. **会话字段**：采访 SSOT，不为可视化再加一轮问。
2. **GddModel + Markdown**：字段和给人复制、交给 ForgeaX 的文档；`renderGdd` 继续。
3. **GddView + 封面资源**：只服务结果页。游戏类型由**代码**从 GddModel 派生，不另存一份，也不让模型自由起名。

**AI 生成数据，不生成可执行 UI。** 不让模型输出 WXML、CSS、组件树。封面 Prompt 只用已确认字段拼装，禁止新物件名、禁止把字画进图。

封面回答「这是什么、什么感觉」，游戏类型回答「属于哪类、什么体验倾向、什么基本形态」，关键瞬间回答「实际怎么玩」，手风琴回答「具体设计」。第一阶段版面从上到下：

1. 真封面（失败则色块）+ 标题 + Pitch。右上角是低权重的 ForgeaX 署名（正式 Logo 44rpx + 20rpx 文字，Logo 和游戏名字号同高，随屏宽和标题等比缩放，不抢标题），是页面叠加，不写进生图提示词。只在生成中显示「封面生成中」角标。主人预览在封面下有「重新生成封面」。
2. **游戏类型**：直接铺在页面底板上，没有外层卡片，也没有「类型 / 标签」小标题。第一组是类型芯片，字稍大、字重更高、描边用一点品牌色；第二组是更细的标签芯片，字更小、中性描边。两组都从同一左沿起，自动换行。下面一行是基本形态，例如「单人 · 网页 · 2D · 横屏」；没填的不猜。类型最多 3 个，标签最多 6 个，没有可靠证据就不凑数，也不回退成「休闲」。还没分类完时先出形态，芯片随后出现。芯片的字号、颜色和间距是功能版，等 ForgeaX Design Token 确定后再统一调整。
3. **关键瞬间**：核心机制的视觉化预览层，是截图画廊，不是信息卡。模块落在页面底板上，只有图片有圆角和细描边。静止时第一张图片比上面「游戏类型」的文字再靠左一截；「关键瞬间」、机制标题和介绍仍和「游戏类型」同一条内容左沿。横滑区贯穿屏宽，可以滑过左右内容边距，下一张露出一截，最后一张能完整滑进画面。图片、标题、介绍作为一组一起滑。核心机制是唯一内容来源。有几条就有几张，顺序跟优先级一致；一条都没有则整块不出现。不放进手风琴、完整文档折叠或共创页入口卡。字只有两级：「关键瞬间」和每一条机制标题同一套，复用游戏宪法标题；介绍复用手风琴正文。手风琴里「核心幻想：……」整行只有正文这一级，机制标题不跟那一行。这里不重复游戏类型。
4. 草稿条（规则不变）
5. 章节手风琴：游戏宪法 → 这是什么游戏 → **怎么玩**（动作 / 交互 / 机制）→ **为什么继续玩**（循环 / 爽点 / 奖励 / 成长）→ 胜利与失败 → …。展开收回约 200ms。点另一块时，视角跟到那一块的标题，不停在上一块展开后的底部。自己的预览里，点一句只出荧光绿描边，背景和字色不变，下面展开「修改 / 取消」，点「修改」去改；分享页只读。
6. 完整文档默认收起。游戏名和一句话 Pitch 仍是原来的标题和引用样式，「复制全文」始终在。收起时 Pitch 下面是一行更轻的「点击展开完整文档」，没有分隔线。展开后这个入口消失，正文从游戏宪法排到文末（How 与 Why 两章，编号 2 / 3；Win 起顺延为 4–8），高度跟真实内容走，不裁最后一章；「点击收起完整文档」只在正文末尾。收起约 220ms，并滚回游戏名和 Pitch。收起只是展示；「复制全文」仍复制整份 Markdown。上面的章节手风琴各自展开，互不影响。
7. 分享给朋友（小程序卡片）+ 导出 GDD 文件（仅主人预览；发给文件传输助手即相当于保存在微信里）

**游戏类型不进 GddModel。** 词表仍是 Steam 商店公开标签 `tagdata/populartags`。模型阅读已确认文档后，只能返回词表里的 tag id；服务端再校验 id、类别、数量、信心，以及内容边界里的否定句。结果按会影响分类的字段做指纹，缓存在会话里。打开文档的 GET 不等模型；指纹变了才在后台重分。证据和信心只进调试，不进页面。人数、平台、画面、方向仍按已有呈现字段直接映射：自己玩 / 要和别人一起 → 单人 / 多人，电脑 / 手机 / 网页 → PC / 手机 / 网页，平面 / 能转视角的立体 → 2D / 3D，横屏 / 竖屏原样保留。

**关键瞬间与核心机制是同一份数据。** `GddModel.mechanics` 仍是字符串列表，不另存一套瞬间、不调模型重起标题或改写介绍。GddView 在展示时把每一句拆成标题和正文：第一处冒号前是标题，后面是介绍；没有冒号就整句当标题。手风琴和完整 Markdown 仍印原来的整句。预览里改、删、增或重排某一条核心机制后，重新打开文档，对应卡片跟着变，因为两边都读这一份列表。

每张卡的 `mechanicId` 由机制原文算出，不用数组下标。在预览里点改某一条以后，这一条沿用原来的 id（会话里记在 `mechanicIds`），所以玩法图还跟着它，只是标成已过期。封面回答「看起来是什么感觉」，关键瞬间回答「具体怎么玩」。玩法图只绑定这一条机制，生图时不改标题、介绍、数量和顺序。

文档第一次成型时，封面和还没有图的玩法图会自动开始。打开预览也会再确认一次缺图的机制。已经画好且指纹没变的图直接显示，不会每次打开都重画。失败不自动重试。改了一条机制，只有对应图标「已过期」并留着旧图；改了世界、主角、幻想、美术或呈现，全部玩法图标过期。过期和失败都要用户点这一张的「重新生成」才重画。没有整组「生成玩法预览」按钮。

封面和玩法图走同一个生图队列。封面是最高优先级，第一次玩法图次之，单张重画再次之。还没开始的封面可以排到还没开始的玩法图前面。正在画的那张不中断。并发默认 2（`IMAGE_CONCURRENCY`）。每张图按 `sessionId + mechanicId` 存在 `data/gameplay`，和封面目录分开。离开预览页不会取消已经开始的生成。

玩法图向 `gpt-image-2` 请求 `1536x864`（严格 16:9）。预览框也是 16:9，图片铺满这个框。点图看的是同一张最新图。微信本地文件名带这次生成的时间：同一次继续用缓存，重新生成以后才下载新文件。

导出的 Markdown 仍不带这些图。分享页和首页示例打开的只读文档会显示源会话已有的玩法图：`GET /api/share/:id` 用 `GameplayPipeline.peek`（与主人打开时同一套 `publish` 判定，但不对账、不落盘、不排队、不生图）给出每条的状态，地址换成快照作用域的 `/api/share/:id/gameplay/:mechanicId`，不暴露会话 id；当前图和过期但文件还在的旧图都显示，没有图的只留文字。小程序本地缓存按 `share-<快照 id>` 命名，和主人自己的缓存分开。

封面在定稿/出文档之后**异步**生成，页面先出结构再换图。GET `/api/session/:id` **仍然不跑 extract、不堵生图**。点封面本身不生图。预览上用「重新生成封面」才出新图。会话里一旦有过封面（成功或失败），再改文档不再自动生图；指纹对不上时对外报 `stale`，仍给同一张图的地址。图的地址只跟这张图的生成时间走，过期、重画中、重画失败都不换地址。微信不直连 LiteLLM：图由本服务 `/api/session/:id/cover` 下发，小程序 `downloadFile` 后再显示。

默认出图模型是 LiteLLM 上的 `gpt-image-2`（`.env` 的 `IMAGE_MODEL`，Key 复用对话代理）。出一张约 2MB 的图可能要 1–3 分钟，角标「封面生成中」期间请等。失败则色块，文档照常打开。可用性已在《旧村新炊》实弹走过。

第二阶段再做：爽点卡、成长时间轴、世界短句排版。封面「再出一张」已用预览按钮「重新生成封面」落地。第三阶段再做美学 moodboard。明确不做可玩原型、不做 AI 现场拼卡片布局。

## 7. 明确不做 / 尚未当作产品承诺

当前产品**不做**：自动在 ForgeaX 里立项、按 DSL 选型、生成可玩原型、对话里报「第几轮/第几节」、让模型生成结果页 UI 代码、把导出文件写入系统「文件」App / 相册 / 下载目录。

已承诺（见 §5.6）：真封面、游戏类型（1～3 个类型 + 最多 6 个标签 + 基本形态）、关键瞬间（机制标题 + 机制说明 + 按核心机制自动生成的 16:9 玩法图）；Markdown 仍只交接正文。核心幻想、循环和机制仍在手风琴和完整文档里。

以后再做，本说明书不假装已上线：

- 分享页展示关键瞬间、把玩法图嵌进导出的 Markdown、为分享另存一份裁好的 16:9 文件
- 游戏类型芯片的字号、颜色和间距。当前是功能版，等 ForgeaX Design Token 确定后再统一调整
- 爽点卡、成长时间轴、世界短句、美学 moodboard、点封面本身重生图（预览已有「重新生成封面」按钮）
- skill 风格化文档
- 账号 / openid / 云端长期保存（现在是本机会话 + 可选文件或 Postgres）
- GDD 存放位置与生产环境补齐项
- 聊天形态「产品化气泡 vs agent」的最终选型（现在按产品化一来一回做）
