---

## 1. 它是什么

**Newbee** 是 ForgeaX 的前置共创：用户丢一个贫瘠脑洞，经过一轮引导对话，得到一份人可读的游戏设计文档（GDD）。文档目前是**手动交给** ForgeaX 继续做游戏，不在本产品里做选型、编排或可玩原型。

一句话链路：

```text
脑洞 → 同意引导 → 按节澄清（带方向卡）→ 口头概念总结 → 定稿三选 → Interactive GDD 预览 / 分享卡片 / 导出文件
```

**不是**「填一句 prompt 就出完整游戏」，也不是当前 README 旧稿里的 DSL / match-3 / catalog 选型。仓库里还留着那些包和历史设计文档，它们**不是**现在对用户承诺的产品。

---

## 2. 成功长什么样

用户走完一轮之后，应能指着屏幕说：

- 这就是我想做的游戏（有暂定名和一句话亮点）
- 我是自己点「定稿」才看到文档的，不是系统自己弹出来的
- 中间每问到一个设计缺口，我都能点方向，也可以自己打字
- 出文档之后我还能继续改：可以在共创里打字走定稿三选，也可以在预览里点手风琴一句，高亮后点右侧 ✎，确认后只改清单里的那些地方

## 3. 用户看见的流程

### 3.1 开口

助手先打招呼，请用户随便说一个画面、玩法或角色。用户无固定身份。

### 3.2 同意门（宿主写死）

用户说出想法之后，再问要不要走创意引导。文案大意：大约 **10 轮**提问，把创意澄清成设计文档。

固定两张卡：

| 选项 | 行为 |
| --- | --- |
| 是，开始创意引导 | 进入采访。下一句必须已经在聊他的创意，不再问要不要走流程 |
| 不用，先不走这个流程 | 自由说想法，不投喂方向卡，能确定的就记下 |

**「大约 10 轮」只是给用户的范围，不是收口条件。** 到第几问、出不出三选、出不出文档，都不数轮次。内部按大约 15 问排：前面四节可以稍多，后面四节收短；子项能合并就合并。不改同意门文案。

### 3.3 采访（模型写方向，宿主要卡）

同意之后，按节问（已能跳过的节除外）。每轮：

1. 人话：共情 + **一个**问题（不要在气泡里再列 A/B/C）
2. 底部 **2–3 张实质设计方向卡**：彼此真正不同，label 自带画面，不写「方向 A」
3. 输入框始终是开放口，**禁止**「我有其他想法 / 自己输入 / Other」做成卡片

节的顺序（对用户不要报「第几节」）：

| 内部节 | 要聊清什么 | 能否跳过 |
| --- | --- | --- |
| 破冰 | 用户已经开口 | 已开口则跳 |
| 火花 | 兴奋点（`spark`） | 已有脑洞则心里钉住即可 |
| 核心体验 | 主情感、世界或主题、视听氛围（不问点/拖） | 否；缺口能合并就合并 |
| 核心交互 | 怎么操作、操作谁、屏幕立刻怎样；一句带 → 的链路 | 否；一轮可写多个字段 |
| 核心循环 | 头几秒、奖励/失误（能填则填）、最舍不得删的瞬间 | 否 |
| 成长与变化 | 越玩越多、眼前目标、玩一阵后能做的新事 | 用户或循环里已标明短局 / 一次性 / 纯叙事 / 无长线则可跳；只写 `growth.none` 不够 |
| 美学与手感 | 高光夸奖或手感隐喻，一轮 | 否 |
| 世界与叙事 | 世界或故事 | 已有世界/叙事可跳 |
| 平衡与心流 | 怎么上强度或为什么再来一把，一轮 | 否 |
| 呈现 | 在哪玩、平面还是立体。不问手指怎么点 | 否 |

前面四节（体验 / 交互 / 循环 / 成长）可以稍多；后面四节（美学 / 世界 / 平衡 / 呈现）大约各一轮。列出的子项按缺口合并，不必一问一项。

核心体验、核心交互、核心循环、美学、平衡、呈现：**必须各问至少一轮**，即使模型已经顺带写过字段。

### 3.4 口头概念总结 → 定稿三选

宿主先判定 **核心体验到呈现都已经按节问过**（内部到达第 10 节 / 呈现问完，`may_write_summary: true`）。这之前提示词要求模型不要写暂定名；**一旦人话里已经流出合格概念总结（含提前写出的），底部必须出定稿三选**，不得改成采访卡，也不得把气泡换成另一段采访问句。

到达第 10 节之后，本轮必须出口头概念总结。完整度清单（禁止情感、六池关键词等）**不挡住**写总结，也**不挡住**出三选。那些缺口只影响内部 `gddComplete`；预览顶上亮不亮「这是草稿」见 §5.3，版面上打不打「（未写）」见 §5.5。

助手人话出现**合格概念总结**之后，换成宿主写死的三张卡。

合格总结必须同时有：

- 游戏名：`暂定名` / `暂定游戏名`，或 `《标题》`
- 总结块：`📌`，或「概念总结」，或「一句话亮点」

只说「骨架已经清晰」「蓝图已经成型」**不算**。模型 JSON 里出现定稿项也**不能**换卡。

**流式人话在弹出卡片时不得替换。** 纠偏只补卡片，不换段落。本轮气泡是总结 → 三选；本轮气泡是提问 → 该问的方向卡。

总结出现后：

- 内部进入收敛节（不再继续塞呈现采访）
- 已流出的追问留在气泡里，不裁
- 底部固定三选：

| 选项 | 行为 |
| --- | --- |
| 就按这个定稿，写成设计文档 | **当轮没有方向卡**，出 GDD，底部出现「游戏文档已成型 / 打开预览」 |
| 核心对，但要改某一块 | 先出一轮针对「改哪一块」的实质方向卡，用户点完再回到这三选 |
| 还想再挖挖感觉 / 玩法 | 同上，先一轮设计方向，再回到这三选 |

用户也可以打字「现在就生成」：采访中途立刻出带缺口的半成品，下一轮继续问；口头总结之后效果等同点定稿。

### 3.5 出文档之后

分两种：

- **采访中途主动要文档**：出带缺口的草稿，当轮没有方向卡，下一轮继续当前采访节。不跳到定稿三选，也不要求完整度。
- **点定稿（或总结之后再说要文档）**：输入框不锁；再开口先给一轮针对这句话的设计方向，下一轮再回到定稿三选；文档按新内容重编。

两种都可以打开预览、用小程序卡片分享 **GDD 快照**（不带聊天记录），主人还可以导出 Markdown 文件交给 ForgeaX。文档按采访来写，可以润色延申；没聊过的作品名不要写。

预览上手风琴一行的改法见 §3.7，不走本节的定稿三选。

### 3.6 不同意引导

不弹方向卡。用户自己说，系统只记能确定的部分。他若主动要文档，仍按「有实质内容 + 用户要文档」出草稿。

### 3.7 预览里点一行改

出过预览之后（含中途半成品），用户可以在手风琴里点**一行**来改，不必整份再定稿。

**能点：** 核心动作、交互链路、编号机制、宪法、标了「（未写）」的行，以及其它手风琴正文行。

**不能点：** 封面、游戏基因、分镜、三环、底部完整 Markdown。分享页只读，不能点行。

流程：

1. 点一句先高亮，右侧出现绿色 **✎**（和单个字一样大，右对齐）。再点 ✎ 才回到**同一条**共创。助手只问这一处想怎么改，不报第几节，不出定稿三选。刚问怎么改时还可以打开预览。补丁三选出现时，藏掉「游戏文档已成型」。
2. 用户说完后，**同一轮**用大白话列出文档里会改哪些地方（不说「手风琴」），并弹出补丁三选（宿主写死，不是定稿三选）。写入的字段只留改完后的现行正文，禁止「不再需要旧的，而是通过新的」。

| 选项 | 行为 |
| --- | --- |
| 应用这些改动 | 只把清单里的字段写入文档，再编预览并回去看。清单外的字段不动。第一版不能单行勾选，点应用等于整包接受 |
| 再改改说法 | 不写文档，留在共创继续说这一行；说完再出清单和三选 |
| 取消 | 不写文档，回预览。这次点进来的对话留在历史里 |

改完后：半成品还回采访方向卡，接着挖。已经定稿的，**不把定稿三选还回去**，共创里只留「游戏文档已成型」。点应用或取消都会收掉补丁三选。

**封面：** 第一次定稿、还没有封面时，仍自动出第一张。会话里一旦有过封面（成功或失败），再改文档不再自动生图。预览上用「重新生成封面」才出新图；点封面本身不生图。按钮进行中不可再点；失败只 toast，文档照常。

**旧分享：** 点应用或重生封面后，以前分享出去的**同一份会话**下的快照会跟着变（仍不带聊天）。旧文件如果没有记下是哪条会话，跟不了，也不迁数据。

完整度门不放宽。补「（未写）」可能让草稿/齐活标记变化，规则仍按 §5。

### 3.8 导出 GDD 文件（交给 ForgeaX）

小程序**写不进** iPhone「文件」或系统下载目录。沙盒里的 `saveFile` 用户在手机里找不到。能把文件拿出去的通路是微信发送面板（`wx.shareFileMessage`）。

预览页两件事分开，都保留：

| 入口 | 对方拿到什么 |
| --- | --- |
| 分享给朋友 | 小程序卡片。对方打开的是预览页快照，不是文件 |
| 导出 GDD 文件 | 一份 `{游戏名}-gdd.md`，内容就是预览里的完整 Markdown，**不带聊天、不带封面图** |

点「导出 GDD 文件」后弹出微信发送面板：

- 选**文件传输助手** ≈ 保存在微信里，需要时再转存。产品文案按这个说「保存在本地」，**不承诺**写入系统相册或「文件」App。
- 选好友 / 群 ≈ 把这份文件发到微信。

「复制全文」仍在，文件没发出去时可以先复制。分享页第一版**没有**导出（对方只有快照；交接仍由主人导出）。仍**不**自动在 ForgeaX 里立项。

`.md` 若被客户端拒，同一次点击改写成 `{游戏名}-gdd.txt` 再发，内容仍是 Markdown。微信开发者工具**模拟器发不了文件**（会提示请用真机），要以真机预览为准。预览页不另写说明文案。

## 4. 谁说了算：宿主 vs 模型

**硬规则写在代码里，提示词只负责把模型往规则上推。** 模型可以忽略提示词；宿主必须把结果扳回来。

| 事项 | 谁决定 |
| --- | --- |
| 同意门两张卡的文案 | 宿主写死 |
| 定稿三选的文案和出现时机 | 宿主写死 |
| 补丁三选（应用 / 再改改 / 取消） | 宿主写死；点应用才写清单字段，不走定稿出稿闸 |
| 采访 2–3 个方向的**内容** | 模型按「选项编写纪律」现编 |
| JSON 没有方向卡时 | 宿主再要一轮 options；**已流出的人话不换** |
| 人话里的 A/B 列表 | 收回成卡片；气泡原文不动 |
| 要不要出文档 | 宿主：用户点定稿或说「现在就生成」（中途也可以） |
| 文档里有没有没聊过的作品 | 宿主：没出现过的作品名丢掉；其余栏允许按采访润色 |
| 模型自称 `ready_for_synthesis` / `stage_complete` | **忽略** |
| 问什么、暂定名叫什么、共情怎么写 | 模型；宿主不编内容 |

选项编写纪律（skill 里有全文，这里是产品约束）：

- 2–3 个方向必须彼此真的不同，不是程度词
- label 自带画面
- 禁止开放口选项
- 已经给了卡片，气泡里的原文仍保持流出时的样子

## 5. 「内容齐了吗」其实是四套门

不要把它们混成一句「AI 觉得齐了」。模型不判断齐全，宿主用字段是否非空来算。

### 5.1 采访能不能问下一节

本节该填的字段已经有字，**并且本节已经问过**，才进下一节。一次只进一节。

常见坑：用户口语里说过「3D 画风」，如果没写进「平面还是立体」，呈现节仍会认为不齐。这会挡住进入第 10 节（因而挡住总结和三选），直到呈现问过并写入。

### 5.2 能不能出定稿三选

看**这一轮已经流到屏幕上的人话**：

- 合格概念总结（游戏名 + 一句话 / 📌）→ 定稿三选，即使还没到第 10 节
- 普通采访问句 → 该问的 2–3 个方向卡，不因历史里曾经有过 📌 就改成三选

第 10 节只决定何时**让模型写**总结（`may_write_summary`），不拿来在出卡时换掉已流出的字。**不等** completeness.md 全绿，**不数**大约 10 轮。

### 5.3 能不能出设计文档

同时满足：

1. 用户点了定稿，或说了「现在就生成」这类要文档的话（采访中途也可以）
2. 对话里已经有一点实质内容（pitch / 情感 / 循环 / 机制等任一有字）

**不要求**已经到达第 10 节，**不要求**完整度清单全绿。主动要文档就给半成品。

预览顶上的「这是草稿」只在**中途**说「现在就生成」这类话、而且助手还没给过合格口头总结时亮。模型已经写出概念总结、用户再点定稿，条不亮——即使内部 `gddComplete` 仍是 false。

文档按采访来写，**可以润色和合理延申**，不必每个字都在对话里出现过。内容边界、呈现边界必须有一句，不能空着。没聊过的参考作品名不要写进去。刷新会话也不能凭空再弹文档。**第一次定稿和之后刷新走同一条抽取覆盖**，不用首句 spark 或固定内容边界把 Pitch、核心幻想、「这是什么游戏」占住。

给人看的文档由代码组装，细则见 §5.5。完整度清单仍按 completeness 算，**不再**用顶上草稿条去标总结后的文档。

### 5.4 文档算不算「定稿完整」

对齐 `prompts/game-gdd-clarify/completeness.md`。缺一项 `gddComplete` 就是 false，但不挡住出文档，也**不单独决定**预览草稿条。完整度里「禁止情感」、六类关键词每类 ≥5、参考作品、宪法等经常是缺口。创新性自检五条**没有写进代码**，只在提示词里劝模型。

这三件事不要混：

| 账 | 管什么 | 不管什么 |
| --- | --- | --- |
| `gddComplete` / completeness.md | 内部是否「清单全绿」 | 不出文档、不挡三选、不单独亮草稿条 |
| 预览顶上「这是草稿」 | 中途「现在就生成」且还没有合格口头总结 | 禁止情感/六池缺了也会在总结后的定稿预览里灭条 |
| 版面上的「（未写）」 | 模板里仍要印的格子空着、且文档不算完整 | 禁止情感、避开、空词池、空参考作品整节——那些是省略，见 §5.5 |

### 5.5 给人看的文档怎么收（版面）

GDD **不是**模型整篇写出来的。会话字段进 `toGddModel`，再 `renderGdd` / 小程序章节卡。GET 会话会重新组装，旧聊天不用重聊，打开预览就是当前规则。

**机制 / 高光**

- 给人看时折叠近义，最多 6 条机制、高光用列表（不要顿号墙）。
- 出稿抽取时 `mechanics` / `juice` **整表替换**；采访中途仍并集，以免聊到一半丢掉。

**空栏：省略 ≠ 从会话删掉**

没聊过的内容，字段在会话 JSON 里可以仍是空的，只是有的不印、有的印「（未写）」。

整行或整节**不出现、不打「（未写）」**：

- 禁止情感
- 刻意避开
- 参考作品（借鉴和避开都空则整节没有）
- 关键词池（见下）
- 游戏宪法里没确认过的项（核心幻想、核心循环、美术规则、内容边界、呈现边界、成长规则、世界观规则、UI 规则这八项里，没聊过的整行删掉）。失败规则、爽点、难度不是宪法项，不要灌进宪法。

模板里其它格子（Pitch、循环、疲劳、屏幕方向等）**标题还在**。空着且 `gddComplete` 为 false 时，Markdown / 章节卡仍可能写「（未写）」。完整度全绿时空栏改成「本游戏无此项，不单列。」一类话。

**关键词池（六池）**

六类：玩法 / 情绪 / 世界观 / 视觉 / 叙事 / 玩家动机。

- **不问**：不要为凑齐六池单开一轮采访。
- **不回填正文**：禁止把核心动作、机制段落、整句情绪切碎填进池子。
- **只留短词**：无句号/问号/冒号，大约不超过十二个字；每类最多 10 个。句子进不了池。
- **空则省略**：某一类没有短词就不出那一行；六类都空则整节「关键词池」不出现。
- **完整度仍要每类 ≥5**：这是内部账，经常因此 `gddComplete` 为 false；不因此在总结后的预览顶上亮草稿条。

所以会出现：发光食堂六池在会话里是空数组 → 文档没有这一节；香火未尽抽取时写下了「塔防、香火、老宅」这类短词 → 六行都在。不是两套规则，是两份会话当时有没有留下短词。

**其它版面**

- 核心幻想和玩家身份：一段已经包含另一段就只留一段，不要拼出 `。。`。
- 游戏宪法只印已确认的八项，顺序固定；没聊过的行省略。
- 内容章不要把世界和核心动作硬接在一起。
- Markdown / 手风琴「怎么玩」印核心动作、核心交互、核心机制；循环、爽点、奖励、成长印在「为什么继续玩」。上面的分镜和三环标题仍是「一局怎么转」，不改采访。
- 宏循环用三十分钟循环；长线目标和它不是一回事时多写一行「长线」。
- 「要和别人一起」就打开多人章（排行榜/偷师等），不要只停在呈现栏口语。

### 5.6 Interactive GDD（结果页）

结果页不是「再让模型写一版 UI」，也不是把 Markdown 扔掉。三套账分开：

1. **会话字段**：采访 SSOT，不为可视化再加一轮问。
2. **GddModel + Markdown**：字段和给人复制、交给 ForgeaX 的文档；`renderGdd` 继续。
3. **GddView + 封面资源**：只服务结果页。分镜帧、基因芯片、循环节点由**代码**从 GddModel 派生。

**AI 生成数据，不生成可执行 UI。** 不让模型输出 WXML、CSS、组件树。封面 Prompt 只用已确认字段拼装，禁止新物件名、禁止把字画进图。

打开预览，用户大约 10 秒内应能说出名字、画面、手指干什么。第一阶段版面从上到下：

1. 真封面（失败则色块）+ 标题 + Pitch + NewBee × ForgeaX
2. 草稿条（规则不变）
3. 游戏基因（幻想 / 情感 / 差异化 / 在哪玩）
4. 「你怎么玩」分镜（点下一步）
5. 「一局怎么转」三环（点开原文）
6. 章节手风琴：游戏宪法 → 这是什么游戏 → **怎么玩**（动作 / 交互 / 机制）→ **为什么继续玩**（循环 / 爽点 / 奖励 / 成长）→ 胜利与失败 → …。自己的预览里，点一句先高亮，右侧出现绿色 ✎，再点 ✎ 去改；分享页只读。
7. 完整文档 + 复制全文（How 与 Why 两章，编号 2 / 3；Win 起顺延为 4–8）
8. 分享给朋友（小程序卡片）+ 导出 GDD 文件（仅主人预览；发给文件传输助手即相当于保存在微信里）

封面在定稿/出文档之后**异步**生成，页面先出结构再换图。GET `/api/session/:id` **仍然不跑 extract、不堵生图**。点封面本身不生图。预览上用「重新生成封面」才出新图。会话里一旦有过封面（成功或失败），再改文档不再自动生图。微信不直连 LiteLLM：图由本服务 `/api/session/:id/cover` 下发，小程序 `downloadFile` 后再显示。

默认出图模型是 LiteLLM 上的 `gpt-image-2`（`.env` 的 `IMAGE_MODEL`，Key 复用对话代理）。出一张约 2MB 的图可能要 1–3 分钟，角标「封面生成中」期间请等。失败则色块，文档照常打开。可用性已在《旧村新炊》实弹走过。

第二阶段再做：爽点卡、成长时间轴、世界短句排版。封面「再出一张」已用预览按钮「重新生成封面」落地。第三阶段再做美学 moodboard。明确不做可玩原型、不做 AI 现场拼卡片布局。
