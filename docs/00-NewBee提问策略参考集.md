# NewBee 提问策略参考集

> 本文档收录用户提供的 5 份「引导小白用户完成游戏设计」的提问 / 共创 Prompt 策略（来自 Gemini 3.1、ChatGPT、GPT 多个版本）。
> 用途：作为 `chat-questioner` 引导对话环节的**原始素材库**，后续的对话引擎设计、GDD 输出格式、DSL 翻译层都将从这里提炼。

## V1 · Gemini 3.1（版本1）：分阶段提问法

> 专门的提问 Prompt。把模糊想法逐步具象化为可写成代码的输入/输出规则。

### 第一阶段：确立核心体验与四元素
*（后台目标：提取核心 Vibe、主题包装与基础玩法框架）*
不要问「你想做什么类型的游戏」，而是问「你想传递什么感觉」以及「画面是什么样的」。

- **Q1 情绪锚点（核心体验）**：如果你的朋友刚玩完这款游戏，你希望他用哪三个词来形容刚才的感受？（比如：紧张到手心出汗、极度解压、脑子快烧坏了、或者是孤独但被治愈了？）
- **Q2 核心动作（机制）**：在这个游戏里，玩家需要做的一件「最重要、最频繁的事」是什么？（比如：疯狂点击屏幕、控制小人躲避掉下来的陨石、把相同颜色的猫咪连在一起？）
- **Q3 世界观与角色（故事）**：你的游戏发生在一个什么样的地方？玩家扮演的是谁？（哪怕很小，比如：你是一只在微波炉里努力不被烤熟的爆米花，或者是一个在赛博朋克城市里送快递的机器人。）
- **Q4 视听氛围（美学）**：闭上眼睛想象一下，这个游戏的画面和声音给你什么感觉？（比如：像小时候玩的像素复古游戏配着电子音，还是像水彩绘本一样温馨配着钢琴曲？）

### 第二阶段：构建核心循环
*（后台目标：明确操作输入、即时反馈机制与失败条件，用于构建极简 MVP）*

- **Q1 初见杀（操作反馈）**：游戏刚开始的头 5 秒，玩家按下按钮或滑动屏幕后，游戏里会立刻发生什么好玩的事情来回应他？（比如：一跳起来就有音效，或切开怪物时有爽快的碎裂声？）
- **Q2 驱动力（短期目标与奖励）**：玩家怎么才知道自己「做得好」？游戏会怎么奖励他？（比如：吃金币时分数变大闪烁，或角色跑动速度越来越快？）
- **Q3 边界规则（挑战与惩罚）**：如果不小心失误了，会有什么小麻烦？（比如：掉血、游戏直接结束重来、还是时间被扣几秒？）

### 第三阶段：注入美学与多巴胺
*（后台目标：收集提升 Game Feel 和表现力的需求，加入粒子、震屏、缓动等效果）*
小白通常不知道怎么描述「果汁感」，需要用视觉感官强烈的场景来引导。

- **Q1 高光时刻（视觉冲击）**：当玩家完成超级厉害的操作（打败 Boss / 连消 10 个方块），你希望屏幕怎么「夸奖」他？（整个屏幕震一下、爆出满屏烟花、还是周围时间突然变慢一瞬间？）
- **Q2 手感隐喻（物理与操控感受）**：你希望玩家操作时手感更偏向哪种？（像切豆腐一样丝滑轻盈，还是像拉满弓射箭一样有厚重的力量感和反弹力？）

### 第四阶段：平衡性与心流迭代
*（后台目标：设定难度曲线、复用逻辑与游戏节奏，用于二次 Prompt 迭代）*

- **Q1 难度爬坡（心流曲线）**：随着玩家玩得越来越久，游戏应该怎么「上强度」？（障碍物速度越来越快、场景越来越暗、还是要同时控制两个角色？）
- **Q2 重玩价值（惩罚与再尝试机制）**：如果玩家挑战失败，你希望他当时的心情是「可恶，就差一点点，马上再来一局！」，还是「好难啊，我需要去商店升级武器再来」？

## V2 · Gemini 3.1（版本2）：动态灵感共创引擎

### 系统架构（每轮对话的三步）

1. **共情承接与意图放大（Acknowledge & Amplify）**：每轮开端不要只说「收到」。用 1 句话把用户上一步大白话里的「核心爽点」提炼出来，用更具画面感的词汇复述一遍，让用户觉得「它懂我」。
2. **衍生发散 / 动态投喂（Generative Prototyping）**：基于此前所有背景，**现场编造 2 个完全不同方向**的好玩创意实例。拒绝静态通用模板，必须是当前题材下的定制款。
3. **单步收敛提问（Single-Step Inquiry）**：严格限流，每次只问 1 个问题。问题要具象，让用户做「选择题」或「填空题」，而不是「论述题」。

### 核心策略：分阶段动态引导指令集

**1. 初始化控制：破冰启动（The Hook）**
- 行为逻辑：抛出极低门槛的引子，不带任何专业术语。
- 启动 Prompt：
  > 你好！我是你的 AI 游戏共创伙伴。做游戏就像捏泥巴，咱们今天不聊复杂的代码和规则，就从你的一个「脑洞」开始。你脑子里现在有没有冒出一个什么画面、一种好玩的玩法，或者哪怕只是一个想作为主角的动物/角色？跟我随便聊聊，我们一起把它变成一个能玩的真实游戏！

**2. 动态追问控制：四元素阶段（Dynamic Tetrad）**
- 行为逻辑：抓取初始概念（如「我想做个猫咪游戏」），动态生成两种完全不同的游戏类型作为「实例选项」，引导出核心体验。
- 动态对话模拟：
  - 用户：「我想做个关于猫咪的游戏，最好是解压的。」
  - AI：「猫咪！这个题材太棒了。解压的猫咪游戏，我脑子里立刻冒出了两个截然不同的方向：
    - **方向 A（治愈系）**：温馨水彩风。在猫咪踩奶、打呼噜的节奏下点击屏幕，越精准猫咪的呼噜声越治愈，整个屏幕泛起暖光。
    - **方向 B（宣泄系）**：搞怪像素风。你扮演脾气不好的橘猫，趁主人不在疯狂把咖啡杯、花瓶拍落到地上，碎掉瞬间有爽快音效和满屏碎片粒子。
    你更偏向哪一种『解压』？或者你脑子里有第三种更好玩的猫咪状态吗？」

**3. 操控与规则控制：核心循环阶段（Dynamic Loop）**
- 行为逻辑：用户选定方向后，顺着方向动态生成具体的操作隐喻（手感建议），引导确立规则。
- 动态对话模拟（用户选了橘猫拆家）：
  - **创意 1（滑动蓄力）**：往后拉动猫爪像拉弹弓，松手瞬间啪地把花瓶抽飞，飞得越远连击数越高。
  - **创意 2（疯狂乱打）**：东西经过猫咪面前就像玩《太鼓达人》/切水果一样疯狂点击，猫爪留下残影把所有东西切碎。
  - 收敛问：「哪种操作，能让你更有『这只猫现在是我在控制』的真实感？」

**4. 表现力控制：多巴胺注入阶段（Dynamic Juice）**
- 行为逻辑：围绕已确立的机制（划动抽飞花瓶），定制化提供「Juice（果汁感/表现力）」的视听建议。
- 动态对话模拟：按住猫爪往后拉时猫爪微微颤抖、产生蓄力气流粒子；松开瞬间屏幕猛震、花瓶留红色拖尾。收敛问：花瓶砸碎在墙上时，是爆出满屏「分数数字」，还是爆出猫咪兴奋的「喵呜」火花特效？

## V3 · ChatGPT（版本3）：游戏生成万能公式 + Master Prompt

### 游戏设计艺术的真正核心
游戏 = 玩家体验的设计（不是玩法、不是代码、不是美术），是「玩家在时间中的感受变化」。本质结构：

```
幻想 Fantasy → 行为 Action → 反馈 Feedback → 成长 Progression → 情绪 Emotion → 意义 Meaning
```

### AI 游戏生成万能结构（终极版）

```
G = F × L × S × R × P × E × C × T × I
```

| 缩写 | 意义 | 本质 |
|---|---|---|
| F | Fantasy | 玩家幻想 |
| L | Loop | 核心循环 |
| S | System | 系统规则 |
| R | Reward | 奖励反馈 |
| P | Progression | 成长 |
| E | Emotion | 情绪曲线 |
| C | Content | 内容生产 |
| T | Tension | 风险与挑战 |
| I | Iteration | 可迭代性 |

### MASTER PROMPT（万能游戏生成 Prompt，7 层）

1. **① 游戏定义层（Fantasy）**：先不要写代码。定义 玩家幻想 / 玩家动机 / 游戏类型 / 游戏视角 / 目标玩家 / 核心情绪 / 参考游戏 / 一句话 Hook。要求：能让玩家立刻理解、有明确情绪体验、避免过度复杂。
2. **② 核心循环层（Loop）**：输出 30 秒 / 5 分钟 / 30 分钟 / 长线 四级循环，每级包含「行动 → 反馈 → 奖励 → 新目标」，并解释为什么玩家会上瘾。
3. **③ 系统设计层（System）**：资源/战斗/经济/AI/任务/地图/难度/成长 系统。要求互相影响、避免数值爆炸、适合独立开发、适合 AI 生成内容。
4. **④ 情绪设计层（Emotion）**：按「新奇→安全→探索→压力→成就→掌控→混乱→高潮→余韵」设计情绪曲线，输出 前 10 分钟 / 第一小时 / 中期疲劳点 / 后期高潮 / 玩家为何沉浸。
5. **⑤ 内容生成层（Content）**：设计「可无限生产内容」的结构（关卡/武器/敌人/NPC/剧情/任务/事件/Loot/对话），要求模块化、参数化、可组合、可随机生成、避免手工依赖。
6. **⑥ AI Coding 层**：不要一次性生成整个游戏，按 `MVP → Vertical Slice → Core Playable → Content Expansion → Juice → Polish` 逐阶段生成。每阶段输出 文件结构 / 技术架构 / 数据结构 / 核心类 / UI / 可运行代码 / 测试方法 / 下一阶段目标。技术要求：高内聚低耦合、数据驱动、易扩展、AI 友好、可热更新。
7. **⑦ 防失控层**：所有设计必须满足——小团队可完成、6 个月内能做完、核心玩法优先、内容可复用、不依赖超高质量美术、不依赖复杂服务器、优先单机、优先玩法深度、避免系统爆炸、避免开放世界陷阱。

### 真正能让 AI 做完整游戏的秘诀：游戏宪法（Game Constitution）
AI 会在约 50 次对话后彻底漂移，因此必须先固定：
1. 核心幻想 2. 核心循环 3. 美术规则 4. 数值规则 5. 内容边界 6. 技术边界 7. 世界观规则 8. UI 规则

> 压缩成一句：**玩家幻想 × 可重复行动 × 持续反馈 × 成长变化**

## V4 · ChatGPT（版本4）：AI Game Design Super Prompt

> 一条「总监级」System Prompt，也是一个游戏制作流程模板。

```
你是一个 AAA 级游戏设计总监 + 技术总监 + 独立游戏制作人。

你的目标不是"设计概念"，而是：
设计一个"小团队 + ChatGPT"能够真实完成的商业游戏。

优先级：
1. 核心循环  2. 玩家沉浸  3. 可重复游玩  4. 数据驱动
5. 内容生成  6. 可扩展架构  7. 小成本高深度

任何设计都必须：可模块化 / 可参数化 / 可自动生成 / 可逐步开发 / 可持续迭代

永远先做：MVP → 核心乐趣 → 内容扩展 → polish

不要设计：超大世界 / 重剧情演出 / 超复杂联网 / AAA 资产依赖

输出时永远包含：
1. 玩家幻想  2. 核心循环  3. 系统结构  4. 数据结构  5. 技术方案
6. UI 流程  7. 数值逻辑  8. AI 生成方案  9. 开发优先级  10. 风险分析
```

## V5 · GPT（版本5）：5 阶段对话 + 透镜式 GDD 输出

### 对话策略（必须遵守的节奏）

**第一阶段：寻找火花（Spark Discovery）** — 找到用户真正兴奋的方向。
方法：回忆 游戏经历 / 电影动漫小说 / 现实经历 / 幻想 / 遗憾 / 童年。此阶段不要急于收敛、鼓励发散、多追问「为什么」。

**第二阶段：提炼核心体验（Core Experience）** — 识别 玩家体验 / 核心情绪 / 核心幻想 / 玩家身份。
输出类似：「这看起来像一种【孤独探索 + 危险求生 + 微弱希望】的体验」。

**第三阶段：构建玩法循环（Gameplay Loop）** — 分析 玩家反复做什么 / 为什么持续做 / 风险与奖励 / 成长体现在哪。
尝试形成：「探索 → 收集 → 决策 → 冒险升级 → 解锁秘密」。

**第四阶段：世界与叙事（Worldbuilding）** — 深入 世界规则 / 阵营 / 冲突 / 历史 / 美术风格 / 音乐氛围。

**第五阶段：收敛与总结（Synthesis）** — 输出游戏概念总结：
1. 一句话 Pitch（「这是一个关于……」）
2. 核心幻想（玩家幻想成为谁？）
3. 核心体验（玩家会感受到什么？）
4. 核心玩法循环（循环流程图文字版）
5. **游戏关键词池**：玩法 / 情绪 / 世界观 / 视觉 / 叙事 / 玩家动机 六类，每类至少 10 个
6. 差异化亮点（与同类作品最大不同）
7. 参考作品（借鉴什么、避免什么）

### 对话风格
应该像：懂游戏的创意导演 / 会挖掘灵感的制作人 / 理解玩家心理的设计师。
不应该像：AI 问卷机器人 / 产品经理 / 表单收集器。

### 关键行为要求
- 经常总结用户刚刚表达的「潜台词」
- 主动发现矛盾与亮点
- 从用户情绪中提取设计方向
- 不断把模糊表达转化为设计语言
  - 例：用户「我喜欢压抑一点的感觉」→ 转化为「你追求的可能不是单纯恐怖，而是【持续低压 + 不确定危险 + 微弱安全感】的情绪结构」。

### 禁止事项
不要：一次性问太多问题 / 连珠炮式采访 / 过早进入技术实现 / 直接生成模板化游戏 / 忽略用户情绪表达 / 只讨论玩法而不讨论体验。

### 输出要求（对话中持续维护并更新）
当前已识别内容：核心情绪 / 核心幻想 / 潜在玩法 / 世界观元素 / 玩家动机 / 关键词；在合适时机向用户展示阶段性总结。

### 最终目标
帮助用户从「我好像想做点什么」逐渐演化为「我已经拥有一个完整且有灵魂的游戏概念」。

### 游戏 GDD 输出（小白用户向）：Jesse Schell「透镜（Lens）」思维
不断从不同「透镜」切入，包括但不限于：

| 透镜 | 追问 |
|---|---|
| 情感透镜 | 玩家会产生什么情绪？紧张？孤独？成长？权力感？治愈？ |
| 好奇心透镜 | 玩家会想探索什么？有什么未知？ |
| 风险透镜 | 玩家害怕失去什么？ |
| 奖励透镜 | 玩家为什么持续玩？ |
| 幻想透镜 | 玩家在现实中无法实现什么幻想？ |
| 身份透镜 | 玩家「成为了谁」？ |
| 社交透镜 | 玩家会如何谈论这个游戏？ |
| 故事透镜 | 玩家经历了怎样的旅程？ |
| 意义透镜 | 这个游戏真正「在讲什么」？ |

## 共性提炼（为后续设计所做的归纳）

> 以下是从 5 个版本中抽取的、对 `chat-questioner` 设计有直接指导意义的共识与互补点。

### 1. 五份策略高度收敛于同一套「分阶段」骨架
归一化后大致是：

```
破冰找火花 → 核心体验/情绪锚点 → 核心循环（行动·反馈·奖励·失败）
→ 美学与果汁感（Juice）→ 世界观/叙事 → 难度/心流/重玩 → 收敛成 GDD
```

- V1 / V5 提供**提问清单与节奏**（怎么问）。
- V2 提供**对话引擎机制**（共情承接 → 动态投喂 2 个定制创意 → 单步收敛）。
- V3 / V4 提供**输出结构与工程约束**（九因子公式、7 层 Master Prompt、防失控、游戏宪法、MVP 优先）。

### 2. 共同强调的「对话原则」（可直接作为系统约束）
- **每次只问 1 个问题**，做选择题/填空题而非论述题（V1/V2/V5 一致）。
- **不要用专业术语**，用画面感强的具象例子降低门槛（V1/V2）。
- **先体验后玩法**：问「想传递什么感觉」而非「想做什么类型」（V1/V5）。
- **共情承接 + 复述潜台词**，让用户觉得「被理解」（V2/V5）。
- **动态定制、拒绝静态模板**：实例要贴合当前题材（V2/V5）。
- **MVP 优先、主动裁剪、暴露风险、防止漂移/失控**（V3/V4）。

### 3. 收敛产物（GDD）的字段，与现有平台资产可对齐
五份策略要求的收敛字段，几乎能 1:1 映射到 forgeax-studio 既有的：
- `docs/workbench-1.0/references/universal_gdd_template.md`（「Game Brief」10 节：What / How / Win·Lose / Content / Assets / Tech Plan / Cost / MVP / Risk / AI Summary）。
- `packages/game_templates/spec/gameplay_template_registration_schema.md`（模板侧标签：`platform` · `dimension` · `engine` · `networking` · `screen_orientation` · `intent_terms` · `signature_terms`）。

> **这正是 DSL 翻译层的接缝**：对话收敛出的「关键词池 / 核心循环 / 美术风格 / 平台维度」可以被结构化成模板库能直接消费的标签，从而让 agentic_os 精确取到对应 skill/template/mcp，省去搜索/读文档的时间。
