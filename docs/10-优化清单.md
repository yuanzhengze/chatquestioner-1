## P0-1 · 打通 S1 闭环：对话产物 → 编排 DSL → 跑出真游戏

**问题**：项目存在**两套互不相通的 DSL**——
- 选择 DSL（`GameDSL`：`constraints/genre/mechanics/modalities`）：对话产出，喂 `resolver`。✅ 已闭环。
- 编排 DSL（`GameDef`：`board/input/systems/goal/rules`）：喂 `orchestrator` 编译跑游戏。✅ 仅能跑硬编码 def。

二者之间**没有任何翻译**，`docs/09` §5 规划的 **S1（对话 → 编排 DSL → 编译 → 跑游戏）完全没连**。

**证据**：
- `apps/playground/src/main.ts` 只加载写死的 `bejeweled / candyCollect`（`DEFS` 常量），对话产物进不来。
- `packages/conversation` 内无任何到 `GameDef` 的产出路径。

**影响**：项目"做出好游戏"价值线的**最后一公里断裂**——目前无法从一段对话得到一个真能玩的游戏。

**验收标准**：
- [ ] 一段对话（或其 `ConversationState` / 选择 DSL）能产出一份合法 `GameDef`（match-3 范围内）。
- [ ] 该 `GameDef` 经 `validate` 无错、`createGame` 跑通，可在 playground 真玩。
- [ ] 至少 1 个端到端 golden：罐装对话答案 → `GameDef` → 可玩。

## P0-2 · 补齐编排运行时：让 Candy Crush 标杆关真能玩

**问题**：`manifests.ts` 声明 18 个模块（首发 14 + 二批 4），但 `MatchEngine` 只实现了子集：swap / match-detect / clear / gravity / refill / cascade / score-combo / move-budget / shuffle / goal(collect|score)。

**运行时缺失**：`board-layer`（果冻层）、`special-tile` / `special-trigger`（特殊糖果）、`spreader`（蔓延）、`drop-collect`、`input-link`、`input-drag-path`，以及 goal 的 `clearLayer` / `drop`。

**证据**：`createGame.ts` 明确注释 `clearLayer / drop 等目标 S0 暂未实现运行时 → 退化为 endless`；`toGoal` 对 hook 目标也退化为 endless。

**影响**：`docs/09` 重点案例 **Candy Crush（§A.2 `candy-crush-jelly-23`）实际跑不起来**，只有 Bejeweled 级别能真玩；§6.8 的 golden 验收（"能玩 + 可构建"）对它无法满足。

**验收标准**：
- [ ] 实现 `board-layer` + `clear-resolve.clearsLayer` + goal `clearLayer`，能跑"清果冻"关。
- [ ] 实现 `special-tile` / `special-trigger`（条纹/炸弹/包装的生成与单个触发）。
- [ ] `candy-crush-jelly-23` 进 golden 且可玩（组合效果仍走 hook，见 P1-1）。

> P0-1 + P0-2 配套做，价值最高：让"对话 → 真能玩的游戏" demo 从断裂变成成立且有说服力。

## P1-1 · 落地 codegen + hook 逃生舱机制

**问题**：`docs/09` §6.6 定义编译器为 `compile(dslSource, index): { files, hooks, used, errors }`（产 TS 文件 + hook stub），§6.7 定义逃生舱机制。实现里 orchestrator 只有 `createGame()`（运行时解释器）+ `validate()`，**没有 codegen、没有 hook stub 生成**。

**影响**：`hook("...")`（红色差异化逻辑、护城河）目前无处安放，只能退化为 endless；§6.8 "生成代码可被 vite 构建" 无法验收。

**验收标准**：
- [ ] `compile()` 产出可构建的 TS（GameInstance/MainScene/config）。
- [ ] `hook("name")` → 生成 `game/core/source/hooks/name.ts` stub 并接好调用点，路径进 `CompileResult.hooks`。
- [ ] 计算逃生舱触发率 `hooks/(used+hooks)`，纳入 golden 健康指标。

> 决策点：codegen vs 运行时解释器（`docs/09` §8 开放问题）。建议 P0 demo 成立后再定，避免过早投入。

## P1-2 · 接通 module-index 构建期闭环 + 模块门控

**问题**：`packages/module-index` 已建，但 `validate.ts` 用的是同进程 `MANIFEST_BY_ID` 对象，未走"构建期生成 `module-index.json` → 编译期消费"这套；`package.json` 也无 `build:module-index` 脚本（对比已有 `build:catalog` 等）。

**影响**：§4.5"模块门控不占 agent 上下文"机制停在纸面；与 `resolver` 的门控合流（§8 开放问题）未推进。

**验收标准**：
- [ ] 加 `build:module-index` 脚本，产出 `module-index.json`（params → JSON Schema）。
- [ ] 编译/校验消费 index，而非硬编码对象。
- [ ] 复用 `resolver` 同一 trigger 词汇做模块门控（genre/modality → 候选模块清单）。
