# NewBee 输出格式分层设计（闲聊 vs 重点）

> 日期：2026-06-08 · 状态：已确认
> 目标：让 NewBee 的「人话回复」在视觉上区分**闲聊文本**与**重点信息**，使用户在前端能一眼识别哪些是过渡铺垫、哪些是需要重点感知/确认的核心内容。

## 1. 背景与目标

NewBee 每轮回复（哨兵 `<<<STATE>>>` 之前的 reply 部分）目前整段交给统一的 `Markdown` 组件（`markstream-react`）渲染，全部呈现为同一种正文样式，用户无法快速分辨"哪些是闲聊、哪些是重点"。

本设计在**不改动现有输出协议与渲染链路**的前提下，通过「原生 Markdown 语义约定 + 提示词规范 + CSS 视觉强化」三者配合，让重点信息醒目可辨。

**不做（YAGNI）**：不改输出协议、不改哨兵切分逻辑、不引入自定义 Markdown 语法、不为不同重点类型设计不同卡片配色（统一卡片样式即可，后续需要再升级）。

## 2. 重点标记的语义约定

NewBee 的人话回复内部约定三种文本形态：

| 形态 | Markdown 语法 | 用途 | 前端渲染 |
|---|---|---|---|
| 闲聊/承接 | 普通文本 | 共情承接、过渡、口语化铺垫 | 默认正文样式 |
| 行内重点 | `**加粗**` | 句子里需让用户抓住的关键词/短句（被提炼的爽点、关键设计词） | 高亮底色 + 主色文字（荧光笔效果） |
| 重点区块 | `>` 引用块，首行以约定 emoji 起头 | 需用户重点感知/确认的整段内容 | 醒目卡片（左色条 + 浅底 + 圆角），emoji 作图标 |

重点区块的三种约定类型（靠首行 emoji 区分语义，前端统一卡片样式）：

- `> 💡 ...` — **关键想法 / 创意提炼**：NewBee 提出的核心点子、对用户潜台词的设计化翻译。
- `> ❓ ...` — **重要引导问题 / 待确认**：需用户拍板的核心选择，对应 [F2] 第 3 步收敛提问、宪法项确认。
- `> 📌 ...` — **阶段小结 / 已定核心**：对应 [F6] 阶段性小结、被钉为"宪法"的确认项。

约束：emoji 仅用于 `>` 引用块首行；普通闲聊不滥用加粗（避免误伤行内高亮）。该约定对所有 assistant 文本面生效（流式回复、历史消息），因为它们都走同一个 `Markdown` 组件。

## 3. 前端渲染实现（纯 CSS）

不改 `Markdown.tsx`（仍是 `markstream-react` + `renderCodeBlocksAsPre`），只在 `apps/web/src/styles.css` 的 `.cq-md` 容器下增量加样式。`markstream-react` 将 `**加粗**` 渲为 `<strong>`、`>` 引用渲为 `<blockquote>`，全靠 CSS 选择器命中：

- **行内高亮（`.cq-md strong`）**：主色文字 + 浅主色半透明底（如 `rgba(主色, 0.15)`）+ 轻微内边距 + 圆角，做成荧光笔效果；暗色面板下保证对比度。
- **重点卡片（`.cq-md blockquote`）**：去掉默认灰竖线引用样式，改为卡片——浅底色、左侧 3–4px 主色色条、圆角、内边距、上下留白。emoji 在首行自然显示作为图标。三种类型共用同一张卡片样式（不按类型变色）。

**流式**：NewBee 输出中 `final={false}`，markstream 处理半截语法。CSS 是声明式的，blockquote/strong 一旦成形即套样式，中途不会错乱，无需为流式做特殊处理。

**测试约束**：沿用 markdown-rendering spec 结论——node 环境无 jsdom，组件不做渲染单测，靠 `pnpm --filter @cq/web build`（typecheck + build）+ 本地 dev 手测验证。

## 4. 提示词改动（让 NewBee 稳定产出标记）

**改动点 1 — `prompts/newbee.system.md` 新增 `[F9] 输出排版规范`**（置于 [F8] 语气之后）：

- 回复分两类文本：**闲聊/承接用普通文本**；**重点用 Markdown 标记**。
- 行内重点：把"被提炼出来的核心爽点/关键设计词"用 `**加粗**`，每段最多 1–2 处，宁缺毋滥。
- 重点区块：用 `>` 引用块承载，首行必须以约定 emoji 起头（`💡` 关键想法 / `❓` 重要引导问题 / `📌` 阶段小结）。
- 纪律：纯闲聊不要加粗；emoji 只在引用块首行用；不因排版堆砌大量重点块（一轮通常 0–2 个区块）。

**改动点 2 — `packages/conversation/src/llm.ts` 的 `TURN_DIRECTIVE` 微调**：

- 在第 1) 部分（面向用户的人话回复）补一句：人话回复可使用 [F9] 排版规范（加粗 + emoji 引用块）区分闲聊与重点，但仍不得出现 JSON/字段名。
- 关键约束：哨兵 `<<<STATE>>>` 之后内容不受影响；emoji 引用块只出现在哨兵之前的 reply 里。现有 `collectStream` 按哨兵切分逻辑无需改动。

**与 options 的关系**：本轮带 `options`（A/B 方向）时，[F2] 已规定人话回复里不再展开方向描述；`❓` 引导问题块此时承载那一个收敛提问本身即可，不与 options detail 重复。

## 5. 改动文件清单

改动文件（共 3 个，全部增量、无破坏性）：

- `prompts/newbee.system.md` — 新增 `[F9] 输出排版规范`
- `packages/conversation/src/llm.ts` — `TURN_DIRECTIVE` 第 1) 部分补排版引用
- `apps/web/src/styles.css` — `.cq-md strong` 行内高亮 + `.cq-md blockquote` 重点卡片

不改动：`Markdown.tsx`、`turn.ts`、`advance.ts`、`ContextStream.tsx`（链路天然兼容）。

**数据流回顾**：LLM 产出含 `**加粗**`/`> 💡` 的 reply → `collectStream` 按哨兵切分（不受影响）→ `parsed.reply` → `ContextStream` → `Markdown` → markstream 渲成 `<strong>`/`<blockquote>` → 新 CSS 套样式。

## 6. 验收标准

1. `pnpm --filter @cq/web build` 通过（typecheck + build）。
2. 本地 dev 手测：NewBee 回复中加粗显示为高亮、`> 💡/❓/📌` 显示为带图标的卡片、普通闲聊为正文。
3. 流式过程中半截语法不报错、不闪烁错乱。
4. 哨兵后的 STATE JSON 不泄露到 reply、不被渲成卡片。

## 7. 风险与对策

- **LLM 偶尔不按 emoji 约定** → 提示词强约束；emoji 缺失时引用块仍套基础卡片样式（优雅降级，不报错）。
- **暗色面板对比度** → CSS 用半透明主色 + 实测调整。
- **加粗误伤**（LLM 在闲聊里随手加粗）→ 提示词明确"纯闲聊不加粗、每段最多 1–2 处"；行内高亮样式保持克制，即便误标也不突兀。
