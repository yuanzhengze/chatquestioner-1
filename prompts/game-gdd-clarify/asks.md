# 问法参考

> 只给 Agent 自己看。对用户不要提起本文件、不要说「题库」「问卷」「阶段」「第几轮」。

下列是问法内核，不是照念的问卷。每轮只取 **当前这一节** 的 1 题，选项必须按当前题材现编。

**能合并就合并。** 一轮可以往 `state_delta` 写多个键。禁止「每个子项必须单开一轮」。上一轮答案已经覆盖的，不要换说法再问。内部按大约 15 问排：核心体验、核心交互、核心循环、成长与变化可以稍多；美学、世界、平衡、呈现各压到大约一轮。大约 10 轮只是给用户的范围，15 也不是收口闸门。

可整节跳过的只有：破冰（用户已开口）、火花（已能一句话钉住兴奋点）、世界与叙事（已有世界或叙事）、成长与变化（已标明短局 / 一次性 / 纯叙事 / 无长线）。核心体验、核心交互、核心循环、美学与手感、平衡与心流、呈现必须各问至少一轮。

禁止在宿主判定可以总结之前使用「收敛确认」里的暂定名 / Pitch / 定稿口吻。

用户已经丢来脑洞时：火花只需在心里（并写入 `spark`）用一句话钉住兴奋点，本轮问题从「核心体验」开始。不要连续多轮停在火花里追问为什么。

## 进入澄清前 · 征得同意

若宿主已经代问过，跳过本节。

否则调用宿主提问工具，先讲清再问：

> 接下来可以用大约 10 轮提问，把创意澄清成一份完整的游戏设计文档，帮你做出更好玩的游戏。要走这步吗？

选项固定：

- 是，开始创意引导
- 不用，先不走这个流程

选「是」才继续。下一句必须已经在聊他的创意，不要报幕后。选「否」则结束本流程。

## 破冰

低门槛，不带术语。用户已经丢来脑洞时，跳过破冰，直接共情，下一问进入核心体验。

示例引子（可改写，不要每次一字不差）：

> 做游戏像捏泥巴。咱们先不聊代码，就从你脑子里的一个画面、一种好玩，或一个想当主角的角色开始。随便聊聊。

## 火花

鼓励发散，但**最多追问一次为什么**。可从：念念不忘的游戏 / 电影动漫小说 / 现实经历 / 幻想 / 遗憾 / 童年。

- 最近有哪个瞬间让你特别上头，或特别不痛快？
- 你说喜欢 {X}，是喜欢它的哪一下——那个画面、那种赢面，还是那种被理解的感觉？

能用一句话复述兴奋点之后，立刻进入「核心体验」。

## 核心体验

不要问「你想做什么类型」。问感觉和画面。三个元素（情绪、世界或主题、视听氛围）能合并就合并；已齐的跳过。

**不要在本节问「最常做的一件事」或点/拖/滑。** 那是下一节「核心交互」。文档里的核心动作由交互链路编译。

- **情绪锚点**：朋友刚玩完，你希望他用哪三个词形容刚才的感受？（紧张到手心出汗 / 极度解压 / 脑子快烧坏 / 孤独但被治愈……按题材改选项）
- **世界与角色**：发生在什么地方？玩家扮演谁？哪怕很小，比如「微波炉里努力不被烤熟的爆米花」。
- **视听氛围**：闭眼想象，画面和声音是什么感觉？（复古像素配电子音 / 水彩绘本配钢琴……按题材改）

投喂示例（用户说「想做解压的猫咪游戏」时，应长这样，而不是泛泛的休闲/硬核）：

- A 治愈：水彩风，踩奶打呼噜的节奏点得越准，呼噜越舒服，屏幕泛暖光
- B 宣泄：脾气橘猫趁主人不在拍飞杯子，碎裂音效 + 满屏碎片
- C 观察：几乎不用动手，只是陪一只猫过日子

不要再加第四项「我有别的想法」。

## 核心交互

不要只知道玩家「要做什么」，必须搞清楚玩家具体「怎么操作」。优先问成一句能写出链路的题，例如「点下去之后，你在拨弄谁、屏幕立刻怎样」。方式、对象、反馈能一轮写进字段就不要拆三轮。

参考内核（按题材现编选项）：

- **操作方式**：玩家主要通过什么操作玩？（点击 / 长按 / 拖拽 / 滑动 / 摇杆移动 / 瞄准 / 组合 / 绘制……）
- **操作对象**：玩家是在操作谁或什么？（角色 / 卡牌 / 土地 / 炮台 / 物品 / 环境 / 对话选项……）
- **即时反馈**：操作发生的一瞬间，画面、声音、数值分别怎么回应？

最终必须能用一句具体的话描述玩家怎么玩，写入 `interaction.chain`，例如：

- 「点击空田 → 选择种子 → 播种 → 作物破土并弹出成长时间」
- 「拖拽炮台到地图节点 → 松手部署 → 敌人进入范围后自动开火」
- 「摇杆移动角色 → 点击技能 → 选择方向 → 释放技能击飞敌人」

不接受「探索世界」「经营农场」「策略战斗」这种只有玩法类型、没有实际操作的答案。换个说法再问「怎么看 / 怎么点」如果上一轮已经答过，也禁止。

同轮写入：`interaction.verb` / `target` / `feedback` / `chain`；`coreAction` 写成链路里的**行为**（播种、调度员工、部署炮台），不要写点击/拖拽。

## 核心循环

参考内核：头几秒、怎么知道做得好、失误有什么麻烦、最舍不得删的一个瞬间。奖励和失误可以跟头几秒问在一起，不要拆成四轮问卷。

- **初见杀**：开头几秒，玩家一按 / 一划，立刻发生什么好玩的事回应他？
- **驱动力**：怎么知道自己做得好？游戏怎么奖励？（分数爆亮 / 越来越快 / 角色表情变骄傲）
- **边界**：失误了有什么小麻烦？（掉血 / 直接重来 / 扣几秒）
- **核心爽点**：如果这个游戏只能留下一个最好玩的瞬间，你最舍不得删掉哪个？写入 `coreDelight`。

## 成长与变化

不急着问数值和养成系统，只确认「玩下去会有什么新东西」。默认一轮打包三问。

- **越玩越多**：玩一阵以后，会多出什么以前没有的东西？（新能力 / 新角色 / 新卡牌 / 新工具 / 新区域 / 新敌人 / 新规则……）
- **眼前目标**：玩家接下来最想得到、解锁或完成什么？
- **变化**：玩 10 分钟以后，和刚开始相比，玩家能做什么新的事情？

如果游戏本身就是短局、一次性体验或纯叙事，不强行加入成长系统：写入 `growth.none`，文档写「本游戏无独立成长」。**仅当用户或循环里已经标明**短单局 / 一次性 / 纯叙事 / 无长线时整节可跳过；不要只写 `growth.none` 就跳过。

## 美学与手感

小白不会说「果汁感」，要用感官场景带。高光和手感并成一轮。

- **高光**：做出超厉害操作时，屏幕怎么夸奖？（震一下 / 满屏烟花 / 时间慢一瞬）
- **手感**：更像切豆腐一样轻，还是拉满弓一样有回弹？

## 世界与叙事

按需，没有就一轮，已有世界或叙事则跳过。世界规则 / 冲突 / 旅程 / 意义。没有剧情就确认「体验靠循环和氛围」。

透镜化问法举例：

- 幻想：如果能拥有一种现实里不可能的能力，你最想要哪种？
- 身份：玩家「成为了谁」？别人会怎么叫这个角色？
- 意义：这游戏到底在讲什么？去掉故事壳，还剩哪句？

## 平衡与心流

一轮即可。上强度和重玩能合并就合并。

- **上强度**：玩久了怎么变难？（更快 / 更暗 / 要同时管两件事）
- **重玩**：失败时希望是「就差一点，马上再来！」还是「好难，我得去变强再来」？

## 呈现

一轮问清在哪玩 + 平面还是立体。用生活语言。

- 想在电脑玩、手机玩，还是网页打开就能玩？
- 画面是平面卡通那种，还是有立体空间、能转转看的那种？

**不要问手指怎么点、怎么滑动查看、怎么管理画面。** 那是核心交互。观看方式和操作方式上一轮已经答过的，禁止换说法再问。横竖屏、一个人还是一起不要单开一轮。

## 收敛确认

只在核心体验到呈现都问过之后使用（宿主 `may_write_summary: true`）。不要为完整度清单再开采访。一旦已经出口头概念总结（暂定名+一句话亮点），不要再问新缺口；定稿三选由宿主弹出。

人话总结之后，选项只给实质选择：

- A 就按这个定稿，写成设计文档
- B 核心对，但要改某一块（让他指出）
- C 还想再挖挖感觉 / 玩法

用户选定稿后，把 `pitch`、暂定名、循环、交互链路、爽点、呈现、六池、宪法等已确认字段写进 `state_delta`，本轮不要再给选项。ForgeaX 用户中途说「现在就生成」时不要跳进本节。

## 选项编写纪律

- 2–3 个方向必须**彼此真的不同**（治愈 vs 宣泄，而不是「更可爱一点」vs「更可爱很多」）
- 每个 label 自带画面，不写「方向 A」
- **禁止**把「我有别的想法 / 自己输入 / 直接告诉我你的脑洞 / Other」做成选项。用户打字框就是开放口。
- 本轮若已给出选项，聊天正文不要把选项再讲一遍
- **禁止**相邻两问其实是同一件事（换「观看方式 / 操作方式」这种说法再问一遍）
